# PCIe Verification (and CXL)

> *"PCI Express has been the workhorse of the data center for twenty years, and every generation makes the verification problem worse. Gen5 doubled the data rate; Gen6 swapped the encoding from NRZ to PAM4 and introduced Flit Mode with strict 236-byte TLP packing rules; Gen7 is now pulling the same trick again with bigger gearboxes to fit the new bandwidth into the same physical lanes. The protocol is layered — Transaction, Data Link, Physical — and the layers interact in ways that only surface at speed: a Strongly Ordered write in the PCIe domain has to stay ordered after it crosses into the AXI domain and back, or you corrupt memory. Sathish Kumar Sivakumar's team at META published four different design approaches before finding an enhanced counter-based method that holds PCIe Gen6 ordering rules across the AXI boundary [PCIe and AXI domain traffic ordering, 2025]. Cadence's formal team recently spent a whole paper on how to *reuse* a Gen6 formal environment for Gen7 by clever gearbox manipulation, because rewriting it from scratch is unthinkable [Reduce, Reuse, Reverify, 2025]. And underneath it all, CXL now rides on top of PCIe to keep CPU and accelerator memory coherent. So what's actually going on in PCIe verification, and why does every generation reopen the same wounds?"*

## What it is — the layered PCIe stack

**PCI Express (PCIe)** is a high-speed serial, point-to-point, layered interconnect originally designed to attach peripherals to a CPU and now the backbone of data-center fabrics. The three layers — **Transaction Layer** (Transaction Layer Packets, **TLPs**), **Data Link Layer** (ack/nak, retry, sequence numbers), and **Physical Layer** (lanes, encoding, link training) — each carry their own corner cases. PCIe 6.0 made the picture materially harder by introducing **Flit Mode (FM)**: TLPs are packed into fixed 236-byte Flits under strict packing and alignment rules, with frequent data shifting that traditional formal data-integrity techniques cannot handle [ACT with Confidence: Formal Verification of Packet Based Designs using Array Centric Tracking, 2025]. A Gen6 switch that must translate between Flit Mode and Non-Flit Mode when the Ingress and Egress ports sit at different speeds adds a new translation layer whose routing-logic penalties conventional integration testing simply cannot detect [Streamline PCIe 6.0 Switch Design with effective Verification strategies, 2024].

Layered on top of PCIe is **CXL (Compute Express Link)**, a low-latency fabric that maintains coherency between CPU memory and memory attached to CXL devices. CXL is itself three sub-protocols — CXL.io (PCIe semantics), CXL.cache, and CXL.mem — which makes verification a multi-layer problem from unit level through post-silicon [CXL Verification using Portable Stimulus, 2024]. Critically, both PCIe and CXL have become security-sensitive: the **Layered IDE (Integrated Device Electronics) Packet Security Framework** encrypts and authenticates TLPs, opening a new class of verification blind spots around error detection, state transitions, and resource management [Guardians of the Chip, 2025].

## How it's used in practice

The dominant practical pattern is **formal verification of the protocol layers**, often ahead of simulation. Sharma et al. attack the **Credit-Based Flow Control (CBFC)** at the heart of PCIe — the mechanism by which a requester tracks buffer space across the link — using model checking to reach deeper state space than simulation can manage [Traversing the Abyss: Formal Exploration of Intricate State Space, 2025]. Appikatla and Ramaiah tackle the Flit-packing problem with **Array Centric Tracking (ACT)**, a formal data-integrity technique designed for packet-based designs where complex packing, shifting, and alignment defeat traditional proof methods [ACT with Confidence, 2025]. The Cadence team's *Reduce, Reuse, Reverify* strategy for the Gen6-to-Gen7 transition is a reuse case study: by manipulating the **gearbox** that manages protocol timing for the higher bandwidth, they refine protocol constraints, timing assumptions, and data path configurations rather than rebuilding the formal environment from scratch [Reduce, Reuse, Reverify, 2025].

On the simulation and stimulus side, **Portable Stimulus Standard (PSS)** has become the preferred tool for managing PCIe's combinatorial complexity. Thottathil and Gururaj use PSS to model CXL scenarios — discovery of CXL hierarchy, enumeration of DVSEC registers, mailbox transactions — compiled into a binary that runs on QEMU-emulated CXL hosts and devices [CXL Verification using Portable Stimulus, 2024]. Ganapathy et al. apply PSS over a configurable SV-UVM testbench to drive multiple PCIe controllers of varied configuration concurrently, generating more vectors and covering more corner cases in the same duration [Acceleration of Coreless SoC Design-Verification using PSS on Configurable Testbench in Multi-Link PCIe Subsystems, 2021]. Performance verification has its own discipline: Mehta et al. compute expected Flit throughput by hand (e.g. 6,400 bytes over x8 lanes at 4 ns Flit latency) and compare against a VIP performance banner to catch bugs that pass functional checks but miss their throughput target [Streamline PCIe 6.0 Switch Design, 2024]. NVMe-over-PCIe takes it further, combining simulation with simulation acceleration via Accelerated Verification IP to reach 300x–700x speedup on 50–100 MGate designs transacting 10 IOPS [NVMe Development and Debug for a 16 x Multicore System, 2019].

## Pitfalls and where the field is heading

The deepest pitfall is **cross-domain ordering**. When PCIe TLPs cross into the AXI domain — as they do in any modern SoC — PCIe ordering rules must survive the translation. Sivakumar et al. document four design approaches for ensuring Strongly Ordered (SO) writes complete only after all preceding Relaxed Order (RO) writes; the early ones suffer performance and dependency issues, and only an enhanced counter-based method using unique RO IDs hits full Gen6 throughput with minimal overhead [PCIe and AXI domain traffic ordering, 2025]. Formal environments also have their own reuse trap: Fazal et al. note that even minor spec ambiguities — like exactly which EIEOS symbol patterns are valid — can produce real bugs the formal run only exposes once timing assumptions are tuned for the new generation [Reduce, Reuse, Reverify, 2025].

The field is converging on three trends. First, **multi-protocol UCIe chiplet** systems inherit PCIe/CXL semantics across die boundaries, demanding dynamic protocol environments that switch flavors on the fly [Protocol Environment: A Dynamic approach to Enable Multi-Protocol UCIe Design Verification, 2024]. Second, **security verification** of the IDE framework is becoming first-class, with targeted techniques around state machines, error detection, and resource handling for both PCIe and CXL [Guardians of the Chip, 2025]. Third, the early-2010s **multi-methodology VIP** work that aligned the three EDA vendors on UVM [From the Magician's Hat: Developing a Multi-Methodology PCIe Gen2 VIP, 2011] has matured into reusable, generation-portable formal and PSS environments — the same intellectual instinct (write the protocol once, reuse it everywhere) just pushed up several layers of abstraction.
