# Smart Regression and Test Selection

> You have a regression with ten thousand tests and a code change touching three files. The honest engineering answer to "which tests do I rerun?" has, for decades, been "all of them, just in case." It is the safe answer and the expensive one — full regressions eat compute budgets, stretch overnight windows, and still ship feedback hours after the bug was introduced. The ML pitch is appealing: train a model on past runs, learn which tests historically fail given which code changes, and rerun only the ones likely to catch something. Done well, you get the safety of a full regression at a fraction of the cost. Done naively, you ship a bug because the model decided the relevant test was "redundant." The DVCon corpus on this topic is small but pointed, and the shift from coverage-directed heuristics to learned models is now well underway. So how did we get here?

## What it is and where the manual flow breaks

**Smart regression and test selection** is the application of machine learning — neural networks, graph neural networks, instance-based predictors, multi-armed bandits — to the question of which tests to run, in what order, and with what parameters, given a finite compute budget. The motivation is empirical: in production IP verification environments, a manual sanity regression consumes four to eight engineer-hours per iteration, with most of that effort spent on log inspection, rerun management, and waveform navigation rather than root-cause analysis [A Novel Fast Regression, 2026]. The bottleneck is not execution; it is the human glue between execution, triage, and debug.

The classical precursor is **coverage-directed test generation**, which uses statistical or Bayesian models to pick stimuli that close coverage fastest. **Accelerate Functional Coverage Closure Using Machine-Learning-Based Test Selection** reports up to 2x speedup in coverage closure on a 5G channel-estimation block by using a neural-network-based selector that also reduces redundant tests [Accelerate Functional Coverage Closure Using Machine-Learning-Based Test Selection, 2023]. The same paper is candid about the limitation that traditional constrained-random verification alone is insufficient for complex designs, which is what pushes teams toward ML in the first place.

The modern framing is workflow-level, not algorithm-level. **Smart Sanity Regression (SSR)** integrates change-impact analysis, intelligent testset optimization, failure clustering, and waveform debugging into a single end-to-end flow, and demonstrates that the selected subset produces coverage identical to the full regression — no functional scenarios lost [A Novel Fast Regression, 2026]. The point is that the AI techniques existed already as standalone capabilities; the productivity gain comes from orchestrating them so the engineer no longer has to manually sequence execution, data handoff, reruns, and debug.

## The model zoo: from neural selectors to graph networks

Different test-selection problems call for different model families. **Test Smarter, Not Harder** addresses post-silicon validation, where thousands of tests run across multiple SKUs and domains with limited observability and legacy suites that have incomplete documentation. It frames test selection as a *graph-based similarity search* over test metadata and uses **Graph Attention Networks (GAT)** to embed tests by their intent descriptions, categorical attributes, and historical dependencies, then clusters and selects representative tests [Test Smarter, Not Harder, 2025]. The graph formulation matters because legacy test corpora are relational — tests share fixtures, depend on prior runs, and reuse setup — and a flat feature vector throws that structure away.

For pre-silicon coverage closure, **A Scalable Gray-Box Instance-Based Reachability Predictor** takes a different tack. It builds an *instance-based* model that predicts which simulations are expected to reach uncovered DUT modules, prioritizing tests likely to contribute new coverage and skipping redundant ones, and pairs the predictor with an optimal batch-scheduling approach that addresses the parallelization mismatch traditional ML suffers from in heavily parallelized simulation farms [A Scalable Gray-Box Instance-Based Reachability Predictor, 2025]. The "gray-box" framing is the interesting part: pure black-box ML ignores the design's structure, while pure white-box reasoning does not scale; the middle ground uses lightweight reachability information as a learned prior.

Parameter tuning is a third sub-problem. **Smart Regression Planner (SRP)** formulates test-parameter configuration as a blackbox optimization problem and uses Bayesian optimization with nightly-regression coverage as feedback to drive parameter updates, automatically exploring the input space that engineers typically set once and never touch again [Test Parameter Tuning with Blackbox Optimization, 2022]. The most aggressive vision is **Multi-Agent Orchestration for Autonomous Regression Management**, which proposes an AI-driven closed-loop architecture in which each run's failure and coverage signals feed directly into the next triage and follow-up decisions, removing the human manager from the relay path entirely [Multi-Agent Orchestration for Autonomous Regression Management, 2026].

## Pitfalls, validation, and what is still hard

The single biggest risk in any test-selection system is *selecting away the bug*. If a model labels a test as redundant and a future change happens to break exactly the scenario that test would have caught, you have shipped a regression. The honest mitigation reported in the corpus is empirical validation against the full regression: SSR's authors confirm coverage parity between the selected subset and the full run before trusting the flow as a pre-regression gate [A Novel Fast Regression, 2026]. That is a strong check for coverage-driven scenarios but does not protect against corner-case bugs that no test in the suite currently covers — a fundamental limitation no selector can solve.

A second class of pitfalls is workflow rather than algorithmic. Standalone AI capabilities — change-aware selection, automated failure clustering, waveform analysis — still require engineers to coordinate execution order, data handoff, rerun policies, and debug workflows, which fragments the process and limits the overall impact of automation [A Novel Fast Regression, 2026]. Closed-loop architectures that feed run outcomes back into the next iteration are an attempt to fix this, but they introduce their own failure modes: silent feedback loops, model drift as the design evolves, and the difficulty of explaining *why* a test was deprioritized when an engineer asks [Multi-Agent Orchestration for Autonomous Regression Management, 2026].

Where the field is heading is convergence. Coverage-directed generation, instance-based reachability prediction, GNN-based similarity search, and Bayesian parameter tuning are all attacking facets of the same problem — given finite compute, what should I run next? The unifying trend is to treat regression as a closed control loop in which ML models propose, the simulator disposes, and the coverage and failure signals train the next proposal. Post-silicon validation is arguably the harder proving ground because of limited observability and legacy documentation, and progress there is a leading indicator that the pre-silicon flows will hold up [Test Smarter, Not Harder, 2025].
