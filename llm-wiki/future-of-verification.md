# The Future of Verification

> *"Walk into any DVCon keynote in 2026 and you'll hear the same word: agents. Not long ago the future-of-verification track was about coverage models and constrained-random solvers; now it's about LLM-powered agents that instantiate VIPs, triage failures, manage regressions, and reason about why a property failed. The 2026 DVCon US program alone shipped at least half a dozen agentic-AI papers from Samsung, NVIDIA, and Cadence. Is it hype? Partly. Is it real? Also partly — the LLM-generated assertions and VIP instantiations still fall short of human quality, but the gap is closing fast enough that teams are already worrying about a new operational problem: **token cost**. Here's where the field is actually heading, grounded in what the corpus says rather than what the keynotes promise."*

## LLMs enter the verification flow

The most concrete inroad is in the parts of verification that look like software engineering. NVIDIA's work on LLM-driven VIP instantiation uses **retrieval-augmented generation (RAG)** to feed the model only the relevant RTL context for each VIP type, then asks it to instantiate checkers across modules — but explicitly notes that current LLM-generated assertions "often fall short of human-level quality," and that the token window is the binding constraint when working with large design files [Towards Automated Verification IP Instantiation via LLMs, 2025]. Cadence's **DUET** attacks the deeper problem: RTL encodes dynamic, time-evolving behavior in low-level SystemVerilog syntax that LLMs struggle to infer, so DUET mimics how a hardware engineer would build understanding by running experiments and tests on the design rather than reading it cold [DUET: Agentic Design Understanding via Experimentation and Testing, 2026].

For formal verification, **FVDebug** combines waveforms, RTL, and design-practice knowledge to automate the root-cause analysis of property failures — a task that historically consumed hours to days per bug [FVDebug, 2026]. The pattern is consistent: LLMs are not replacing verification engineers; they are being slotted into the specific bottlenecks where reading, summarizing, and correlating across artifacts is the actual job. The corpus repeatedly frames the LLM as an agent with constrained context, not as an oracle — and the engineering effort goes into choosing what to retrieve, what to ignore, and how to validate the output.

## Agents take over regression management

Regression is where agentic AI is moving fastest, because the loop is well-defined: run tests, observe failures and coverage, decide what to do next. Samsung's 3-tiered agentic framework restructures regression into user, block, and central tiers — each aligned with a distinct verification scope — and uses a publish-subscribe backbone so the system stays stable under continuous design changes where monolithic scripted pipelines break [A 3-tiered agentic AI Framework for Verification Regression, 2026]. A companion paper proposes an AI-driven closed-loop architecture in which each run's outcomes feed directly into the next triage and follow-up decisions, removing the human manager as a relay between siloed failure and coverage signals [Multi-Agent Orchestration for Autonomous Regression Management, 2026].

Post-silicon is getting the same treatment: a conversational AI system orchestrates a Scandump Parsing Agent, an Elasticsearch-based RAG module (hybrid search, because debug data needs both semantic understanding and exact keyword matching), and a Jira Integration Agent to automate what used to be raw-dump archaeology [An AI Agent Framework with Elasticsearch for Scalable Post-Silicon Debug Automation, 2026]. The bet across all of these is that verification will look less like running tests and more like supervising systems that run tests for you — with the human role shifting toward setting qualification criteria, reviewing agent decisions, and intervening when fault-locality needs to be preserved.

## What humans still do — and the new problems agents create

The corpus is candid about what AI does not yet solve. Verification still requires flexible testbench architecture and OOP discipline to survive last-minute DUT changes and parallel execution [Testbench flexibility as a foundation for success, 2021]; system-level random verification at SoC scale remains a methodology problem, not an AI one [System-Level Random Verification, 2019]; languages like VHDL 2018 and methodologies like **UVM-FM** keep evolving to make modeling layered protocols tractable without AI's help [VHDL 2018: New and Noteworthy, 2018; UVM-FM, 2018]. Decades-old methodology lessons — like Lockheed Martin's parameterized base agents and constraint-driven stimulus on the GOES-R satellite FPGAs — remain relevant because they encode hard-won architectural discipline [Weathering the Verification Storm, 2013].

Meanwhile, AI introduces entirely new problems. The most novel is cost: continuous regressions generate tens of thousands of logs, and "traditional EDA infrastructure has no native notion of LLM cost," leaving verification leads unable to answer what the triage bot cost last week — **Passive Token Accounting** is an early answer [Passive Token Accounting For Cost-Aware LLM Assistance, 2026]. Even hardware-specific workhorses like LPDDR5X PHY verification with DFE remain largely human-driven methodology papers, not AI showcases [The Road to Robustness, 2023]. And on the design-automation side, ML is being slotted into narrow but useful niches, like recognizing patterns in natural-language register specifications to auto-build the IP and SoC register environment [Using Machine Learning in Register Automation and Verification, 2019]. The honest summary: the future of verification is hybrid, with agents absorbing the triage and correlation work and humans still owning architecture, intent, and judgment.
