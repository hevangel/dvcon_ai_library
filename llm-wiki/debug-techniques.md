# Debug Techniques and Tools

> *"There's a moment every verification engineer knows: the test fails at 2am, the waveform is 800 cycles deep, the failure is 200 transactions away from the cause, and you're the one on call. The Wilson Research data says engineers now spend more time on debug than on anything else in the project, and on a 200M-gate design that's not a tooling problem — it's a methodology problem. The good news is that the DVCon corpus has been quietly building an answer for fifteen years: **triage as a first-class discipline**, transaction tagging, IP-XACT-aware bus tracing, and most recently LLM-driven assistants that read the waveform for you. Some of these kill the obvious bugs; some just stop you from spending a day finding the right engineer. Let's look at the toolkit."*

## Triage: the neglected half of debug

The single most repeated insight in the DVCon debug literature is that **triage** — the front end of debug where failures are sorted, grouped, and routed — is where the real time goes, and it has been historically under-served [Failure Triage: The Neglected Debugging Problem, 2012]. The core challenge is recursive: figuring out who owns a bug requires debug, but the owner is the one best placed to do that debug. In practice most triage is done from checker or assertion signatures, which is "better than random" but imprecise, especially when many checkers share failure patterns [Failure Triage: The Neglected Debugging Problem, 2012].

Mentor's "Evolution of Triage" reframes triage as a distinct engineering role — one that depends on cumulative experience as much as quick analysis — and identifies four kinds of triage activity, including the high-value ability to spot systemic failures across the regression history [Evolution of Triage, 2016]. The throughline is that good triage is about maximizing the value of subsequent debug: choosing the right test cases, allocating them to the right expert, and surfacing common root causes instead of treating symptoms one at a time. As designs and regressions get larger, this specialization is becoming a recognized job function rather than an afterthought.

## Interactive and class-based debug in SystemVerilog

Once a failure lands with the right engineer, the next battle is reproduce-and-probe. SystemVerilog has historically lacked native interactive debug — a gap that Microsemi's **UVM Interactive Debug Library** fills using SV-DPI, allowing a running simulation to be driven from a command prompt: read/write registers through the UVM RAL, create and randomize sequences on any sequencer, or invoke user-defined SV functions and tasks [UVM Interactive Debug Library, 2017]. Mentor's earlier work similarly leverages UVM sequences to build a command-line debugger that can probe both the hardware and the sequences themselves [Command Line Debug Using UVM Sequences, 2011].

For class-based testbenches — which have become "as complex as the hardware under test" — Edelman's "Better Living Through Better Class-Based SystemVerilog Debug" argues that the usual RTL debugging techniques need to be retooled: object identity, factory overrides, and phasing all require different probing strategies than waveform scrubbing [Better Living Through Better Class-Based SystemVerilog Debug, 2012]. At PMC-Sierra, scaling debug to 200M+ gates required methodical investment in debug turnaround time, periodic simulation-state saving, and accepting that the root cause is just as often software interacting with hardware as it is RTL [Can You Even Debug a 200M+ Gate Design?, 2013]. The recurring lesson: on large designs, the bottleneck is rarely the simulator — it is the engineer's loop length.

## Automation and AI-assisted root cause

The newer wave automates what humans used to eyeball. **Transaction tagging** and data-mining — applied at Infosys — automatically cluster pre-silicon failures by signature, surfacing the genuinely new bug hidden among hundreds of known errors [Pre-Silicon Debug Automation using Transaction Tagging and Data-Mining, 2014]. Samsung's **Bus Trace System** uses IP-XACT metadata to walk the full bus connection for each instance and pinpoints bus-hang and error-response scopes from simulation logs alone, removing waveform triage entirely for that class of failure [Bus Trace System, 2024]. Integrated verification platforms for memory designs unify log analysis, automatic debug rerun, waveform correlation, and coverage analysis in one environment, with modularized checkers extracting fail keywords and instance locations [A Platform-Based Approach to Reduce Verification Turn-Around Time in Memory Designs, 2026].

LLM-driven assistants are now crossing from research into practice: **FVDebug** combines waveforms, RTL, and design-practice knowledge to automate the root-cause analysis of formal verification failures [FVDebug, 2026]; Samsung's AI-driven debug uses deep-learning models alongside SystemVerilog assertions and UVM reporting to classify AXI-channel failures with greater than 97% accuracy and F1-scores approaching 0.99 [AI Driven Advanced Debugging in SoC Design Verification, 2026]. A parallel thread — verifying the **debug unit** of superscalar RISC-V cores — shows the other face of "debug" at DVCon: making sure the on-chip debug hardware itself is correct under random debug requests, external interrupts, and pipeline mixes [Verification Methodology for Debug Unit of a Superscalar RISC-V Processor, 2024; Random Testcase Generation and Verification of Debug Unit for a RISC-V Processor Core, 2023]. The newest regression papers — Samsung's Smart Sanity Regression and multi-agent orchestration — push debug automation all the way back into test selection and closed-loop triage [A Novel Fast Regression, 2026; Multi-Agent Orchestration for Autonomous Regression Management, 2026].

- **Command Line Debug Using UVM Sequences** (2011, DVCon US) — Mark Peryer. Leverages UVM sequences to build a command-line debugger for both hardware and sequence bugs.
- **Better Living Through Better Class-Based SystemVerilog Debug** (2012, DVCon US) — Rich Edelman, Raghu Ardeishar and John Amouroux. Retools debug techniques for object-oriented UVM testbenches that rival the DUT in complexity.
- **Pre-Silicon Debug Automation using Transaction Tagging and Data-Mining** (2014, DVCon India) — Kamalesh Vikramsimhan, SenthilKumar Narayanaswamy and Deepak Sadasivam. Clusters pre-silicon failures by signature to surface genuinely new bugs.
